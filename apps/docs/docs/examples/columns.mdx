# Columns

Column definitions describe identity, value access, formatting, interaction,
and presentation. The same definition model is used by the core and both
framework bindings.

<FrameworkCode feature="columns" />

## Essential fields

| Field | Purpose |
| --- | --- |
| `key` | Reads a field from row data and provides a stable fallback identity |
| `colId` | Explicit public identity for state and API calls |
| `label` | Visible header label |
| `type` | Selects default comparison, formatting, filtering, and editing behavior |
| `valueGetter` | Computes a value instead of reading `key` |
| `valueFormatter` / `valueParser` | Converts values for display and committed edits |

Users can resize and reorder enabled columns directly. Initial pinning and
visibility use `pinned` and `hidden`; the API and column panel can change both
at runtime. Capture the resulting layout with `api.getColumnState()` and restore
it with `api.applyColumnState(state)`.

:::tip Shared behavior
Put common capabilities such as `sortable`, `resizable`, and `filter` in
`defaultColDef`. An explicit column value always wins.
:::

## Column types and formatting

```ts
import { ColumnType, type ColDef } from "@agility-workbench/grid";

const columnDefs: ColDef[] = [
  { key: "name", label: "Name", type: ColumnType.STRING },
  { key: "quantity", label: "Quantity", type: ColumnType.NUMBER },
  { key: "active", label: "Active", type: ColumnType.BOOLEAN },
  { key: "createdAt", label: "Created", type: ColumnType.DATE },
  { key: "revenue", label: "Revenue", type: ColumnType.CURRENCY },
];
```

## Value getter, formatter, and parser

```ts
const column = {
  colId: "total",
  label: "Total",
  valueGetter: (row) => row.quantity * row.unitPrice,
  valueFormatter: ({ value }) => `$${Number(value).toFixed(2)}`,
  editable: true,
  valueParser: ({ value }) => Number(value),
} satisfies ColDef;
```

## Pinning, visibility, and capabilities

```ts
const columnDefs: ColDef[] = [
  { key: "id", label: "ID", pinned: "left", movable: false },
  { key: "internal", label: "Internal", hidden: true },
  { key: "name", label: "Name", hideable: false },
  { key: "actions", label: "Actions", pinned: "right", resizable: false },
];
```

Users pin and hide columns through the column menu or the
[column panel](./toolbar-and-views.mdx).

## Explicit width and automatic sizing

```ts
const options = {
  minResizeWidth: 60,
  maxColumnWidth: 360,
  columnDefs: [
    { colId: "name", key: "name", label: "Name", minWidth: 120, maxWidth: 280 },
    { key: "notes", label: "Notes", width: 240 },
  ],
} satisfies GridOptions;

// Fit columns to their rendered content (one columnWidthsChanged for the batch).
api.autoSizeColumns(["name", "notes"]);
api.autoSizeAllColumns();

// Set widths in pixels, as a resize-handle drag would.
api.setColumnWidth("name", 180);
api.setColumnWidths([
  { colId: "name", widthPx: 180 },
  { colId: "notes", widthPx: 320 },
]);

// Stretch or shrink the unpinned columns to fill the centre viewport.
api.sizeColumnsToFit();
```

A declared `width` is the column's width: the grid does not resize it to fit
the data, only clamps it to the column's own `minWidth` / `maxWidth`. A column
without a `width` is sized to its header and content on the first data load,
floored at `minResizeWidth` and capped at `maxColumnWidth` (a column's own
`minWidth` / `maxWidth` take precedence over those two). Once a user drags a
column edge, that width wins until an explicit fit-to-content: double-clicking
the resize handle or calling `autoSizeColumns` / `autoSizeAllColumns` measures
content even for a column with a declared `width`. Widths set with
`setColumnWidth(s)` behave like a drag: clamped to the column's bounds and kept
across later autosizes.

`sizeColumnsToFit()` fits the **centre** section only: the visible unpinned
columns are scaled together, keeping their relative widths, so they exactly
fill the centre viewport. Pinned sections keep their widths (they are
width-clamped and never scroll), as do `resizable: false` columns and the
row-number and checkbox columns. Each fitted column stays within its
`minWidth` / `maxWidth` (falling back to `minResizeWidth` / `maxColumnWidth`),
so when those bounds cannot reach the viewport the fit falls short or
overflows. The new widths count as user widths and arrive as one
`columnWidthsChanged`. Call it after the grid is laid out — before that it does
nothing.

Set `autosizeColumnsOnDataChange: true` (the default for the server-side row
model) to recompute content widths after each data refresh; declared and
user-resized widths are kept. Enable a leading row-number column with
`rowNumbers: true`.

## Cell spanning

```ts
const columnDefs: ColDef[] = [
  {
    key: "title",
    label: "Title",
    colSpan: ({ data }) => data.kind === "section" ? 3 : 1,
  },
  { key: "owner", label: "Owner" },
  { key: "status", label: "Status" },
];
```

A span stops at a pinned-section boundary.

## Conditional cell styling

```ts
const column = {
  key: "change",
  label: "Change",
  cellClass: ({ value }) => Number(value) < 0 ? "is-negative" : "is-positive",
  cellStyle: ({ value }) => ({ fontWeight: Number(value) > 10 ? "700" : "400" }),
} satisfies ColDef;
```

## Header content and whole-cell components

```ts
const labelOnly = ({ displayName }) => {
  const strong = document.createElement("strong");
  strong.textContent = displayName;
  return strong;
};

const columnDefs: ColDef[] = [
  { key: "name", label: "Name", headerComponent: labelOnly },
  { key: "status", label: "Status", headerCellComponent: labelOnly },
];
```

`headerComponent` replaces header content while preserving grid controls.
`headerCellComponent` replaces the whole header cell except its resize handle.
The framework bindings accept React/Angular components in both slots.

## Column state

```ts
const savedState = api.getColumnState();

// Later: restore widths, order, pinning, and visibility.
api.applyColumnState(savedState);

// Exact restore: hide columns absent from the saved state.
api.applyColumnState(savedState, { defaultState: { hidden: true } });
```

Column state carries each column's sort too (`sort`, `null` when unsorted, and
`sortIndex`); see [Sorting](./sorting.mdx#set-or-toggle-sorting-through-the-api).

## Add or replace definitions at runtime

```ts
api.setColumnDefs([...baseColumns, { key: "margin", label: "Margin" }]);

api.dispatch({
  type: "addSparklineColumn",
  targetColId: "revenue",
  colIds: ["jan", "feb", "mar"],
  sparklineType: "line",
});
```
