# Current limitations

The current feature surface is broad, but the following constraints should be
evaluated before adoption.

## Not currently implemented

- Variable or automatic row heights and text wrapping
- Master/detail row panels
- Pivoting on the server-side row model (client-side [pivot](./examples/pivot.mdx)
  is supported)
- Within pivot mode: filters on the generated columns (filters run pre-pivot on
  source rows), in-table row/column grand totals (the footer aggregate row shows
  per-column grand totals), and drag-and-drop *between* the column panel's field
  wells (an entry drags to reorder within its own well; moving between roles is
  the **+** and **×** buttons)
- ARIA exposure of the column-group header hierarchy (parent header cells are
  presentational; leaf headers are full `columnheader`s)
- An in-grid contextual keyboard-shortcut reference

The grid's assistive-technology support — the ARIA grid model, focus and
announcement behavior, and its current boundaries — is described on the
dedicated [accessibility](./accessibility.mdx) page.

## Client-side-only behavior

Quick filter, tree data, full-width rows, custom filter matchers, and row
transactions require the client-side model. Server-side grouping and sticky
group rows are supported, but server-side group sorting is local to each
listing.

The quick filter's [find behavior](./examples/filtering.mdx#find-instead-of-filter)
additionally needs data-row cells to highlight, so it is unavailable while the
pivot layout is displayed (every displayed row there is a group row). In both
cases `getFindState().available` is false and the search filters instead.

Finding in a **very narrow grid** keeps one rough edge. A match the grid cannot
scroll clear of the floating search box is normally uncovered by moving the box
to the opposite edge ([Keeping matches
visible](./examples/filtering.mdx#keeping-matches-visible)), but that only helps
where the grid can hold the box clear of where it already stands — under roughly
twice its width, both edges cover the same cells, so the box stays put and the
match stays behind it. Host the widget in the
[toolbar](./examples/toolbar-and-views.mdx) at those widths, where it sits
outside the data region altogether.

## Server-side differences

The server is responsible for filtering and sorting complete data. As a result,
iteration cannot expose a separate pre-filter/pre-sort universe. Open-ended
listings have provisional row/page counts until a short block establishes the
end.

## Layout

All rows currently have one fixed height. Cell spans stop at pinned-section
boundaries. A span that exists only on some rows can produce a visually
non-rectangular selected region even though the selection model remains a
rectangle.
